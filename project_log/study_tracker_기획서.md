# Study Tracker 기획서

## 1. 프로젝트 개요

### 1.1 프로젝트명
Study Tracker (가칭)

### 1.2 개발 배경
개인 학습 과정에서 여러 과목을 병행하다 보면 과목별 학습 시간, 학습 이력 및 복습 시점을 개별적으로 관리해야 하는 불편함이 발생했습니다.

기존에는 이러한 정보를 별도의 도구나 수동 기록을 통해 관리해야 하므로 학습 현황을 통합적으로 파악하기 어렵다는 문제를 느꼈습니다.

이에 학습 기록과 일정, 복습 주기를 하나의 서비스에서 관리할 수 있는 애플리케이션을 기획하였습니다.

### 1.3 프로젝트 목적
개인의 학습 활동을 체계적으로 기록하고 시각화하여 지속적인 학습 관리가 가능하도록 하는 것을 목적으로 합니다.

### 1.4 프로젝트 목표
- 과목별 학습 시간 및 이력 관리
- 학습 목표와 일정 관리 (정사각형 그리드 기반 커스텀 플래너 제공)
- 복습 시점 관리 및 누적형 알림 제공
- 학습 현황의 시각적 제공
- 스마트폰 및 태블릿(전체 화면·분할 화면) 3중 반응형 UI/UX 지원
- 오프라인 환경에서의 독립적인 서비스 이용 (SQLite 기반 로컬 데이터 관리)
- 사용자 계정을 통한 기기 간 데이터 연동 및 다중 사용자 데이터 격리

### 1.5 기술 스택 및 개발 환경 (Tech Stack)
- **클라이언트 (Client)**
  - 프레임워크: Flutter (Dart)
  - 타겟 플랫폼: Android (스마트폰 및 태블릿 지원)
  - 디자인 시스템: Material Design 3 기반 커스텀 테마 및 3중 반응형 레이아웃 (스마트폰 / 태블릿 전체 화면 / 태블릿 분할 화면)
  - 로컬 데이터베이스: SQLite (오프라인 우선 데이터 저장 및 계정별 로컬 데이터 분리 관리)
  - 백그라운드 서비스: Android Foreground Service 및 상단 알림(Notification) / 잠금화면 연동 타이머
- **백엔드 및 인증 (Backend & Auth)**
  - 서버 프레임워크: Kotlin + Spring Boot 기반 REST API 서버 ([백엔드 포트폴리오 서버](https://github.com/kiryud/test_project_kt_sb) 연동)
  - 인증 방식: 자체 ID/PW 인증(개인정보 최소화) 및 OAuth 2.0 / OIDC (JWT 기반) 소셜 로그인

## 2. 현황 및 문제 정의

### 2.1 기존 학습 관리 방식의 문제점 및 타 서비스 한계
- 학습 시간 측정(타이머), 과목별 기록, 복습 주기를 별도의 앱이나 수동 기록(엑셀 등)으로 각각 관리해야 한다.
- 기존의 정사각형 그리드 기반 엑셀 커스텀 플래너는 한눈에 흐름을 보기 좋으나, 가로로 길게 펼쳐질 때 원하는 분류만 필터링해 보거나 실시간으로 모바일/태블릿에서 조작·요약하기 어렵다.
- 시중 학습 앱(열품타 등)은 타이머와 소셜/경쟁 기능에 치중되어 있어, 개인화된 주간/일간 그리드 이력 관리와 누적 복습 관리까지 하나로 통합된 환경을 제공하지 못한다.
- 태블릿으로 인강이나 필기 앱을 띄워놓고 공부할 때, 분할 화면(Split View)에 최적화된 UI/UX를 제공하는 학습 관리 앱이 부족하다.
- 네트워크 환경이나 기기 변경(스마트폰 ↔ 태블릿)에 따른 데이터 접근성 및 동기화 문제가 발생할 수 있다.

### 2.2 해결 방향 및 본 앱의 특장점 (차별화 포인트)
- **통합 학습 관리 (All-in-One):** 다계층 타이머, 커스텀 그리드 플래너, 누적 복습 리마인더, 동기부여 문구를 하나의 애플리케이션에서 유기적으로 통합 관리한다.
- **독창적인 정사각형 그리드 대시보드/플래너:** 엑셀에서 수동으로 관리하던 고정 축(좌측 연·월·요일 9칸 + 상단 분류) 정사각형 그리드 시스템을 앱으로 구현하고, 원하는 분류만 선택적으로 열람·요약하는 기능을 제공한다.
- **태블릿 3중 반응형 UI/UX 특화:** 스마트폰 화면뿐만 아니라 태블릿 전체 화면, 그리고 필기 앱과 함께 띄우는 태블릿 분할 화면(Multi-window)에 각각 최적화된 3중 레이아웃을 제공한다.
- **오프라인 우선(Offline-first) 및 다중 기기 연동:** SQLite 로컬 저장을 통해 오프라인 사용을 완벽히 지원하고, 계정 연동 시 스마트폰과 태블릿 간 동일한 학습 데이터를 유지한다.

## 3. 서비스 정의

### 3.1 서비스 소개
Study Tracker는 개인의 학습 활동을 기록하고 관리하는 학습 관리 애플리케이션입니다.

사용자는 학습 과목을 분류하고, 타이머를 통해 학습 시간을 기록하며, 대시보드에서 누적 학습 현황을 확인할 수 있습니다.

또한 목표 일정과 복습 시점을 관리하여 학습 계획을 지속적으로 유지할 수 있습니다.

### 3.2 핵심 가치
- `기록:` 학습 활동을 체계적으로 기록한다.
- `시각화:` 축적된 학습 데이터를 직관적으로 확인한다.
- `관리:` 학습 목표와 복습 일정을 관리한다.
- `지속성:` 학습 동기를 유지하고 꾸준한 학습을 유도한다.
- `접근성:` 네트워크 연결 여부와 관계없이 학습 기능을 이용한다.

### 3.3 주요 사용자
개인 학습 활동을 체계적으로 기록하고 관리하려는 사용자.

## 4. 주요 기능 정의

### 4.1 대시보드 및 커스텀 그리드 현황판
학습 현황을 종합적으로 확인하고 엑셀 기반 커스텀 플래너의 경험을 제공하는 메인 화면이다.

- **내가 공부하는 이유 (동기부여 영역):** 대시보드 상단/일부 영역에 사용자가 설정한 동기부여 문구(또는 명언) 표시
- **계획상 오늘 할 일 및 오늘 해야 할 복습 요약:** 당일 예정된 학습 계획과 누적된 복습 대상을 즉시 확인
- **정사각형 그리드 기반 학습 이력/주기 현황판:**
  - 각 셀은 정사각형 그리드 형태(숫자 2개, 문자 1개 내외의 요약 정보 표기)로 구성
  - 좌측 고정 헤더 9칸(`연 / 월 / 월 / 화 / 수 / 목 / 금 / 토 / 일`) 및 상단 고정 헤더(`분류/과목`) 구조로 내부 그리드만 이동·스크롤 가능
  - 원하는 분류만 선택적으로 펼쳐 보거나 요약 확인 가능
  - 7칸(일 단위) 표기 및 주 단위 묶음 표기 지원 (7칸 홀수 특성을 활용한 과반수 대표 상태 표기, 3종 혼재 시 중간값 적용)
- **학습 시간 통계 및 분석:** 과목별·분류별 누적 학습 시간 및 주기 시각화

### 4.2 플래너 (할 일 및 루틴)
학습 목표와 일정을 등록하고 관리하는 기능이다.

- To-do 형태의 간단한 학습 계획 등록 및 수정
- 목표일까지 남은 기간(D-day) 표시 및 진행 상황 관리
- 일일·주간 반복 루틴 설정
- *(확장 고려 기능)* 계획 시 설정한 최소 학습치 달성 여부에 따라 다음 학습 계획과 자동 연결하는 기능

### 4.3 다계층 타임 트래커 (타이머)
과목별 학습 시간을 다계층 구조로 세밀하게 측정하고 기록하는 기능이다.

- **다계층 시간 측정:**
  - 분류 → 과목 선택 후 측정
  - 전체 학습 시간, 전체 학습 중 휴식 시간, 과목별 부분 학습 시간 동시 추적
  - 전체 학습 세션을 유지한 상태에서 과목만 전환(부분 학습 종료 및 타 과목 타이머 재실행) 가능
- **타이머 형태 커스터마이징 및 배터리 최적화:**
  - 아날로그 시계 형태(뽀모도로 원형 등) 및 디지털 시계 형태(LED 스타일 등) 중 선택 가능 (둘 다 제공)
  - 장시간 켜두어도 배터리 소모를 최소화하는 화면 구성 지향
- **백그라운드 실행 지원:**
  - 다른 앱(필기 앱, 인강 앱 등) 사용 또는 화면 잠금 상태에서도 백그라운드에서 끊김 없이 동작
  - 기본 시계 앱과 같이 상단 상태바/알림창(Foreground Notification) 및 잠금화면에서 진행 상황 표시 및 제어

### 4.4 누적형 복습 리마인더 (알림이)
학습한 내용을 잊지 않도록 커스텀 주기에 맞춰 복습 시점을 관리하는 기능이다.

- 학습 계획 및 과목별 커스터마이징된 복습 주기 설정
- 대시보드 및 푸시 알림을 통한 복습 시점 리마인드
- **누적(Stacking) 표시 시스템:**
  - 예정된 복습을 완료하지 않으면 사라지지 않고 누적되어 표시
  - 누적량 및 지연 일수에 따라 단계별 색상(경고도) 차등 표기 및 최대 표시 개수 제어

### 4.5 동기부여 (내가 노력하는 이유)
지속적인 학습을 유도하기 위한 문구 관리 기능이다.

- 독립된 메인 탭이 아닌 대시보드 내 위젯 영역으로 노출하여 공간 효율성 확보 (스마트폰의 협소한 화면 고려, 텍스트 문구 우선 적용 후 이미지 확장 검토)
- 기본 명언 모음집 제공 및 사용자 지정 문구 등록·수정 (일반 앱 설정 페이지와 동기부여 커스텀 관리 영역은 별도 분리)

### 4.6 사용자 서비스 및 인증
사용자 계정을 생성하고 기기 간 학습 데이터를 연동·관리하는 기능이다.

- 개인정보 수집을 최소화한 자체 ID/PW 기반 회원가입 및 로그인
- OAuth 2.0 / OIDC (JWT 기반) 소셜 로그인 지원
- 계정별 학습 데이터 격리 및 다중 기기(스마트폰 ↔ 태블릿) 간 동기화
- 로그아웃 및 계정 관리

## 5. 사용자 시나리오

### 5.1 최초 이용
1. 사용자가 애플리케이션을 설치한다.
2. 별도의 회원가입 없이 서비스를 시작한다.
3. 학습 분류와 과목을 등록한다.
4. 학습 타이머를 이용하여 학습을 시작한다.
5. 학습 종료 후 기록이 저장된다.
6. 대시보드에서 학습 현황을 확인한다.

### 5.2 학습 일정 관리
1. 사용자가 플래너에 학습 목표일을 등록한다.
2. 대시보드 또는 플래너에서 목표일까지 남은 기간을 확인한다.
3. 학습한 내용을 복습 대상으로 등록한다.
4. 복습 예정일에 알림을 확인하고 복습을 진행한다.

### 5.3 계정 연동
1. 사용자가 기존에 로컬 환경에서 학습 데이터를 생성한다.
2. 회원가입 또는 로그인을 진행한다.
3. 기존 학습 데이터를 계정에 연동한다.
4. 다른 기기에서 동일한 계정으로 로그인한다.
5. 기존 학습 기록을 확인하고 새로운 학습 기록을 생성한다.

### 5.4 오프라인 이용
1. 사용자가 네트워크 연결이 없는 환경에서 애플리케이션을 실행한다.
2. 기존 학습 데이터를 조회한다.
3. 타이머 및 기타 학습 기능을 이용한다.
4. 생성된 데이터는 기기에 저장된다.
5. 네트워크 연결이 복구되면 계정 데이터와 동기화한다.

## 6. 화면 구성 및 3중 반응형 UI/UX 설계

### 6.0 3중 디바이스 레이아웃 대응 원칙
학습 환경의 특성상 스마트폰과 태블릿(필기 앱 병행 사용)을 모두 고려하여 모든 화면을 3가지 규격으로 설계한다.
- **스마트폰 (Smartphone):** 세로형 단일 컬럼 기반 컴팩트 레이아웃
- **태블릿 전체 화면 (Tablet Full Screen):** 대화면을 활용한 다단(Multi-pane) 대시보드 및 확장형 그리드 레이아웃
- **태블릿 분할 화면 (Tablet Split-Screen):** 인강·필기 앱과 화면을 분할(1/2 또는 1/3)했을 때 핵심 컨트롤(타이머, 할 일, 그리드 요약)이 깨지지 않고 동작하는 적응형 레이아웃

### 6.1 메인 대시보드
- 학습 동기부여 문구 영역 (내가 노력하는 이유)
- 정사각형 커스텀 그리드 현황판 (좌측 연·월·요일 9칸 고정 / 상단 분류 고정)
- 오늘 할 일 및 누적 복습 대상 요약
- 분류별·과목별 학습 시간 통계

### 6.2 플래너
- 목표 일정(D-day) 및 할 일(To-do) 목록
- 일일·주간 루틴 등록 및 수정

### 6.3 타이머
- 학습 분류 및 과목 선택
- 다계층 타이머(전체 학습 / 과목별 학습 / 휴식) 실행 및 과목 전환
- 아날로그(원형) / 디지털(LED) 뷰 전환
- 상단 알림바(백그라운드) 연동 표시

### 6.4 복습 관리
- 누적 복습 예정 목록 (지연/누적 단계별 색상 표기)
- 복습 주기 설정 및 복습 완료 처리

### 6.5 설정 및 사용자 관리
- 회원가입 및 로그인 (자체 ID/PW 및 OAuth 2.0 소셜 로그인)
- 계정 정보 및 데이터 동기화 상태 확인
- 동기부여 문구 커스텀 관리 (일반 환경 설정과 분리)
- 애플리케이션 환경 설정 (테마, 타이머 기본 형태 등)

## 7. 서비스 정책

### 7.1 오프라인 사용 정책
- 주요 학습 기능은 네트워크 연결 없이 이용할 수 있어야 한다.
- 학습 데이터는 기기 내 SQLite 데이터베이스에 즉시 저장되어야 한다.
- 네트워크 연결이 복구되면 서버 계정 데이터와 동기화할 수 있어야 한다.

### 7.2 계정 연동 및 단일 기기 다중 사용자 정책
- 회원가입 이전(게스트 상태)에도 주요 학습 기능을 모두 이용할 수 있어야 한다.
- 비로그인 상태에서 생성한 로컬 데이터를 최초 로그인/회원가입 시 해당 계정에 귀속(연동)시킬 수 있어야 한다.
- **동일 기기 내 타 계정 로그인 처리:** SQLite 로컬 DB에 사용자 식별자(`user_id`)를 구분하여 저장함으로써, 같은 기기에서 다른 사용자가 로그인하더라도 기존 사용자의 로컬 데이터가 섞이거나 노출되지 않도록 격리 관리한다.
- 동일 계정으로 여러 기기(스마트폰, 태블릿)에서 동일한 학습 데이터를 이어서 이용할 수 있어야 한다.

### 7.3 데이터 관리 정책
- 학습 데이터는 사용자별로 구분하여 관리한다.
- 로컬 데이터와 서버 데이터의 일관성을 유지해야 한다.
- 동기화 실패 시 로컬 데이터가 유실되지 않아야 한다.
- 여러 기기에서 발생한 데이터 변경 사항을 처리할 수 있어야 한다.
